# Configuring Email/Password Account Features

LobeHub supports email/password account features for signup, password reset, and
admin-managed accounts. The current sign-in page exposes phone OTP and WeChat as
the visible login UI. This guide covers the backend email/password configuration
that still applies to account creation and recovery flows.

## Default Behavior

By default, email/password account features are enabled.
Users can register with their email address and set a password.

## Configuration Options

### Disable Email/Password Account Features (SSO-Only Mode)

If you want to disable email/password signup and password-based account flows,
set the following environment variable:

| Environment Variable          | Type     | Description                                |
| ----------------------------- | -------- | ------------------------------------------ |
| `AUTH_DISABLE_EMAIL_PASSWORD` | Optional | Set to `1` to disable email/password flows |

When enabled:

- The current sign-in page continues to expose phone OTP and WeChat sign-in
- The signup page redirects to the login page
- Users can also authenticate through configured SSO providers

<Callout type={'warning'}>
  Before enabling SSO-only mode, ensure you have configured at least one SSO
  provider via `AUTH_SSO_PROVIDERS`, or another non-password sign-in method.
  Otherwise, users may have no way to log in.
</Callout>

### Enable Email Verification

To require users to verify their email address before signing in:

| Environment Variable      | Type     | Description                              |
| ------------------------- | -------- | ---------------------------------------- |
| `AUTH_EMAIL_VERIFICATION` | Optional | Set to `1` to require email verification |

This requires configuring an email service (SMTP).
See [Email Service Configuration](/docs/self-hosting/auth/email) for details.

## Change Password

Users can change their password in two ways:

1. **Profile Settings**: Go to Settings > Profile to change password
2. **Forgot Password**: Use the reset-password page or admin-supported recovery flow to send a password reset email

<Callout type={'info'}>
  Both methods require email service (SMTP) to be configured for sending
  password reset emails.
</Callout>

## Example Configurations

### SSO-Only (Disable Email/Password)

```bash
AUTH_DISABLE_EMAIL_PASSWORD=1
AUTH_SSO_PROVIDERS=google,github
```

### Email/Password with Verification

```bash
AUTH_EMAIL_VERIFICATION=1
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=noreply@example.com
SMTP_PASS=your-password
```

<Callout type={'tip'}>
  Go to [Environment Variables](/docs/self-hosting/environment-variables/auth)
  for detailed information on all authentication variables.
</Callout>
