# 目录架构

<Callout type={'warning'}>
  本页已按当前中文代码结构更新。英文目录文档可能仍描述旧的 `src/app/[variants]` SPA
  布局，不应作为当前路径依据。
</Callout>

## 顶层目录

```plaintext
lobehub/
├── apps/
│   ├── cli/                  # @lobehub/cli
│   ├── desktop/              # Electron 桌面应用
│   └── device-gateway/       # Cloudflare Worker 设备网关
├── packages/                 # @lobechat/* 共享包
├── src/                      # Web 主应用与服务端
├── locales/                  # 多语言 JSON 构建产物
├── e2e/                      # Cucumber + Playwright E2E
├── docker-compose/           # 开发、生产和自托管编排
├── scripts/                  # 启动、构建、迁移与维护脚本
├── docs/                     # 产品、开发、自托管和 ADR 文档
├── CONTEXT.md                # 项目领域术语
├── package.json              # 根脚本与工作区依赖
└── pnpm-workspace.yaml       # pnpm workspace 定义
```

## apps

| 目录                     | 说明                        | 独立启动方式                    |
| ---------------------- | ------------------------- | ------------------------- |
| `apps/desktop/`        | Electron 桌面端、IPC、主进程和桌面构建 | 根目录 `bun run dev:desktop` |
| `apps/cli/`            | LobeHub 命令行工具             | 目录内 `pnpm run dev`        |
| `apps/device-gateway/` | 基于 Hono/Wrangler 的设备网关    | 目录内 `pnpm run dev`        |

根目录 `bun run dev` 只启动 Web 所需的 Next.js 和 Vite，不会自动启动 CLI 或 Device Gateway。

## packages

`packages/` 是共享能力层，实际目录会持续变化。关键包包括：

```plaintext
packages/
├── agent-runtime/            # Agent 执行循环与编排
├── agent-signal/             # Agent Signal 管道
├── agent-tracing/            # Agent 执行追踪
├── builtin-agents/           # 内置 Agent
├── builtin-skills/           # 内置 Skill
├── builtin-tool-*/           # 单个内置工具包
├── builtin-tools/            # 工具集中注册和 UI 协议组合
├── context-engine/           # 上下文引擎
├── database/                 # schemas、models、repositories、migrations
├── model-bank/               # 模型与 Provider 元数据
├── model-runtime/            # 模型 Provider 适配层
├── types/                    # 跨层共享类型
└── utils/                    # 跨包工具函数
```

不要依赖文档中的包数量；定位能力时应直接查看当前 `packages/` 和对应 `package.json`。

## src/app：Next.js 边界

`src/app/` 不再承载主应用 SPA 页面树。当前主要职责是：

```plaintext
src/app/
├── (backend)/
│   ├── api/                  # Auth、Webhook 等 Route Handler
│   ├── f/                    # 文件访问
│   ├── market/               # 市场服务入口
│   ├── middleware/           # 后端请求中间件
│   ├── oidc/                 # OIDC 路由
│   ├── trpc/                 # tRPC HTTP 入口
│   └── webapi/               # Chat、模型、语音等 WebAPI
├── spa/[variants]/           # SPA HTML 模板服务
└── [variants]/(auth)/        # 必须 SSR 的认证页面
```

主 SPA 页面位于 `src/routes/`，路由注册位于 `src/spa/router/`。旧文档中 `src/app/[variants]/(main)`、`src/app/[variants]/router` 等路径已经不代表当前结构。

## src/spa：入口与路由配置

```plaintext
src/spa/
├── entry.web.tsx             # Web 桌面 SPA
├── entry.mobile.tsx          # 移动端 SPA
├── entry.desktop.tsx         # Electron SPA
├── entry.popup.tsx           # 弹窗 SPA
└── router/
    ├── desktopRouter.config.tsx
    ├── desktopRouter.config.desktop.tsx
    ├── mobileRouter.config.tsx
    ├── popupRouter.config.tsx
    └── desktopRouter.sync.test.tsx
```

`desktopRouter.config.tsx` 与 `desktopRouter.config.desktop.tsx` 必须保持路径和嵌套同步。

## src/routes 与 src/features

推荐结构：

```plaintext
src/routes/(main)/example/
├── _layout/index.tsx         # 薄 layout root
└── index.tsx                 # 薄 page root

src/features/Example/
├── components/
├── hooks/
└── index.tsx                 # 领域页面或公开导出
```

路由文件只应导入和组合 `@/features/*`。业务状态、复杂 UI、数据获取和领域 hooks 应放在 `src/features/<Domain>/`。

当前仓库仍有不少 `src/routes/**/features`，它们是历史结构和迁移债务。维护旧页面时可以按范围逐步迁移，但不要为了目录整洁进行一次性全仓库搬迁，也不要在新页面中继续复制旧模式。

## src/server

```plaintext
src/server/
├── featureFlags/             # 服务端功能开关
├── globalConfig/             # 注入客户端的全局配置
├── routers/
│   ├── async/                # 异步任务
│   ├── lambda/               # 主要业务 tRPC
│   ├── mobile/               # 移动端专用 tRPC
│   └── tools/                # 工具 tRPC
├── services/                 # 可访问数据库的服务端业务
├── modules/                  # 不访问数据库的纯模块
└── workflows/                # 后台工作流
```

## 数据库目录

```plaintext
packages/database/
├── migrations/               # 数据库迁移
└── src/
    ├── schemas/              # Drizzle 表、枚举、索引和关系
    ├── models/               # 数据模型
    └── repositories/         # 跨模型或复杂查询
```

数据库变更必须同时考虑 schema、migration 和相关 model/repository 测试。

## 文档与决策

- `docs/adr/`：已经接受的架构决策。
- `docs/impl/`：阶段性实施或审计记录，可能是带日期的快照。
- `docs/development/basic/handoff.zh-CN.mdx`：后续维护者的统一入口。

详细的数据流和运行时说明见 [架构设计](/zh/docs/development/basic/architecture)。
