# 环境设置指南

<Callout type={'warning'}>
  本页只维护中文版本。英文环境文档可能包含过期命令或缺少本项目的商业配置说明，请以当前
  `package.json`、环境模板和本页为准。
</Callout>

## 环境要求

本地开发需要：

- Git
- Node.js
- pnpm，版本以根 `package.json` 的 `packageManager` 字段为准
- Bun，用于运行根目录 npm scripts
- Docker Desktop 或兼容的 Docker Engine + Compose
- 可用的 PostgreSQL、Redis、S3 和搜索服务；推荐直接使用仓库提供的 Compose

## 1. 安装依赖

```bash
git clone https://github.com/jihaobin/chatslike.git
cd chatslike
pnpm install
```

不要混用 npm、Yarn 和 pnpm 安装依赖。根脚本内部可能调用 npm script runner，但 workspace 依赖仍由 pnpm 管理。

## 2. 创建环境文件

PowerShell：

```powershell
Copy-Item docker-compose/dev/.env.example docker-compose/dev/.env
Copy-Item .env.example.development .env
```

Bash：

```bash
cp docker-compose/dev/.env.example docker-compose/dev/.env
cp .env.example.development .env
```

两个文件职责不同：

| 文件                        | 用途                                  |
| ------------------------- | ----------------------------------- |
| `docker-compose/dev/.env` | Compose 端口、PostgreSQL 密码和 RustFS 凭据 |
| `.env`                    | Next.js、数据库连接、Redis、S3、搜索、模型和商业功能配置 |

`.env.example.development` 中的固定密钥、模拟支付和本地开关仅供开发使用，不能复制到生产环境。接入真实模型时应设置对应 Provider API Key；接入本项目的 New API 网关时应检查 `NEWAPI_API_KEY` 和 `NEWAPI_PROXY_URL`。

## 3. 启动开发基础服务

```bash
bun run dev:docker
```

该命令只启动 Web 开发需要的服务：`postgresql`、`redis`、`rustfs` 和 `searxng`。Compose 中的 `network-service` 和 `rustfs-init` 会作为 RustFS 网络与初始化依赖参与运行。

检查状态：

```bash
docker compose -f docker-compose/dev/docker-compose.yml ps
```

默认地址：

| 服务             | 默认地址                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| PostgreSQL     | `postgresql://postgres:change_this_password_on_production@localhost:5432/lobechat` |
| Redis          | `redis://localhost:6379`                                                           |
| RustFS API     | `http://localhost:9000`                                                            |
| RustFS Console | `http://localhost:9001`                                                            |
| SearXNG        | `http://localhost:8180`                                                            |

## 4. 运行数据库迁移

```bash
pnpm db:migrate
```

需要查看数据库时可使用：

```bash
pnpm db:studio
```

只有修改 Drizzle schema 时才应运行 `pnpm db:generate`，并按仓库迁移规范审查生成 SQL。

## 5. 选择启动模式

### 完整本地 Web 开发

```bash
bun run dev
```

根脚本实际执行 `scripts/devStartupSequence.mts`：

1. 启动 Next.js，默认端口 `3010`。
2. 启动 Vite SPA，默认端口 `9876`。
3. 等待 Next.js 端口就绪并请求根页面完成预热。
4. 任一子进程异常退出时结束整个开发会话。

访问 `http://localhost:3010` 使用 Next.js 提供的完整本地应用；直接访问 Vite 的 `http://localhost:9876` 时，API、tRPC、OIDC 和 WebAPI 请求会被代理到 Next.js 端口。

可以通过 `PORT` 环境变量或 `bun run dev -- -p <port>` 调整 Next.js 端口；Vite 代理会读取相同的 `PORT`。

### 只开发桌面 Web SPA

```bash
bun run dev:spa
```

Vite 默认监听 `9876`，并在终端输出 Debug Proxy URL：

```plaintext
https://app.lobehub.com/_dangerous_local_dev_proxy?debug-host=http%3A%2F%2Flocalhost%3A9876
```

该 URL 使用线上 LobeHub 环境承载本地 SPA，适合前端开发和真实账号联调。它依赖网络与线上后端，不等同于完整本地环境。涉及数据写入时先确认当前账号和环境。

### 移动端 SPA

```bash
bun run dev:spa:mobile
```

默认访问 `http://localhost:3012`。

### Electron 桌面端

```bash
bun run dev:desktop
```

该命令进入 `apps/desktop` 并使用桌面应用自己的开发脚本。桌面端还涉及主进程、preload、IPC 和平台依赖，修改前应阅读桌面开发约定。

### CLI

```bash
cd apps/cli
pnpm run dev
```

开发模式默认使用仓库内的 `.lobehub-dev` 作为 CLI Home。

### Device Gateway

```bash
cd apps/device-gateway
pnpm run dev
```

该服务由 Wrangler 启动，是独立运行目标。

## 6. 验证启动结果

完整本地模式至少检查：

```powershell
Invoke-WebRequest http://localhost:3010 -UseBasicParsing
Invoke-WebRequest http://localhost:9876 -UseBasicParsing
docker compose -f docker-compose/dev/docker-compose.yml ps
```

预期结果：

- Next.js 根页面返回 HTTP 200 或符合当前认证 / 重定向设计的有效响应。
- Vite 返回 SPA HTML。
- PostgreSQL、Redis、RustFS 和 SearXNG 容器正常运行。
- 终端没有某个子进程 “exited unexpectedly” 的错误。

## 7. 构建

完整 Web 构建：

```bash
bun run build
```

只构建 SPA：

```bash
bun run build:spa
```

`build:spa` 只生成 Vite 产物。若要让 Next.js 使用最新 SPA，还必须执行：

```bash
bun run build:spa:copy
```

该步骤会把 `dist/desktop`、`dist/mobile` 中的公共资源复制到 `public/_spa`，并更新 `src/app/spa/[variants]/[[...path]]/spaHtmlTemplates.ts`。

## 8. 常见问题

### 端口被占用

PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 3010,9876,5432,6379,9000,9001,8180 -ErrorAction SilentlyContinue
```

先识别占用进程，不要直接结束不属于本项目的服务。

### 数据库迁移失败

依次检查：

1. `docker compose ... ps` 中 PostgreSQL 是否健康。
2. `.env` 的 `DATABASE_URL` 是否与 Compose 密码、端口一致。
3. 当前数据库数据版本是否与正在使用的镜像兼容。
4. 失败发生在连接、权限、SQL 还是已有迁移冲突。

不要在没有备份和版本核对时删除数据库数据。

### RustFS 或上传失败

检查 `.env` 与 `docker-compose/dev/.env` 中的 access key、secret、endpoint 和 bucket 是否一致，并确认 `rustfs-init` 已创建 `lobe` bucket。

### 依赖异常

先重新运行：

```bash
pnpm install
```

只有确认需要彻底清理时才使用：

```bash
bun run clean:node_modules
pnpm install
```

### 完全重置开发服务

```bash
bun run dev:docker:reset
```

该命令会删除 Compose volume 和 `docker-compose/dev/data`，造成本地数据库与对象数据丢失。执行前必须确认数据可丢弃。

更多架构、接手顺序和当前风险见 [项目接手与维护指南](/zh/docs/development/basic/handoff)。
