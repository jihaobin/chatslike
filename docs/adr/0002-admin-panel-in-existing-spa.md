# 管理后台集成进现有 SPA，而非独立部署

---
Status: accepted
---

## 背景与决策

需要为超级管理员和管理员构建一个后台管理界面，覆盖用户管理、订单查看、使用量分析等场景。

我们决定：**在现有 SPA 内新增 `/admin` 路由段，通过 RBAC 路由守卫控制访问，而非独立部署一个管理应用。**

## 为什么这样做（为何会让未来的读者意外）

独立管理后台是行业常见做法，它的安全隔离边界更清晰。读者可能会问：「为什么管理后台和普通用户界面在同一个 SPA 里？」

原因是：项目已有完整的 RBAC 系统（`rbac_user_roles` 表 + `RbacModel.hasPermission()`）和 better-auth 认证，安全边界可以在应用层而非部署层实现。独立部署意味着单独维护认证流程、CI/CD 流水线、环境变量，对当前规模而言维护成本远超安全收益。

## 考虑过但否决的替代方案

- **独立 Next.js 应用** —— 需要单独部署、单独认证、单独维护依赖升级，与主应用共享代码也变得复杂。否决，当前规模不值得。
- **独立路由组但走 Lambda Router** —— 与现有 TRPC 风格不一致，且跨域数据查询需要手写大量类型。否决，改为 TRPC。
